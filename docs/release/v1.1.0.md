# ScreenClip 1.1.0

ScreenClip comes to your iPhone and iPad: add ScreenClipKit to the Debug build of your app, shake to report what you see, and the report lands in ScreenClip on your Mac, where an agent fixes it.

## New

- **ScreenClip for iOS.** ScreenClipKit is a Swift package for the Debug build of your own iOS app. Shake the device, or take a screenshot and tap **Report**, then annotate with the same tools as on the Mac (arrow, rectangle, ellipse, pen, text, redact), write a note, and tap **Send**. Release builds of your app contain none of it. Settings › **iOS** has **Copy agent prompt**, which asks Claude Code or Codex to install it for you, and the setup code if you prefer to add it yourself.
- **Local server and pairing.** In Settings › **iOS**, turn on **Receive reports from iOS devices** and click **Pair a device…**. Confirm the same 6-digit code on both screens. Reports travel over your local network, encrypted for the Mac you paired, and only paired devices can send them. If the Mac isn't reachable, reports wait on the phone and go out on their own later. **Fetch** asks connected devices to send what they saved, and a saved report can also be AirDropped to the Mac and opened.
- **Reports from iOS are filed like captures on the Mac.** They are routed by the app's bundle ID, and when no project lists it yet, ScreenClip finds it in the project's Xcode project. The project editor suggests the bundle IDs it finds. **Agent for iOS reports** picks the agent, model and effort for them. iOS reports show an iPhone icon, and the report shows the device, OS and screen.
- **Optional diagnostics.** **Attach logs and diagnostics** sends recent app logs, the screen's views and accessibility elements, and device state with a report. Agents are told where they are and open them only when the screenshot and note aren't enough.
- **Status and retest on the phone.** The SDK's settings list what is waiting and what was sent, with each report's number, project, agent, live status and pull request. For a merged fix, **Looks fixed** marks it verified and **Still broken** sends your next capture back to the same report.
- **The Mac stays awake while reports are in flight.** ScreenClip keeps the Mac from idle sleep while a report is queued or an agent is working, while a pull request waits to merge automatically, and, unless you turn it off, while it is receiving iOS reports. The display can still sleep.

## Fixes

- A new project takes its repository's default branch as the base, such as `master`, instead of always `main`. When a project's base branch doesn't exist, the project editor says so and offers the right one, and a report stops with a message that names the branch to use instead of git's “invalid reference”.

## Install

If you have 1.0.3 or later, ScreenClip installs this update on its own: it shows **Update to 1.1.0** in the menu bar popover once it is downloaded, or installs it the next time ScreenClip quits. **Check for Updates…** in the popover's **⋯** menu checks right away.

From 1.0.2 or earlier, download **ScreenClip.dmg** from this release, open it, and drag **ScreenClip** into **Applications**, replacing the older version. Your queue, projects and settings are kept. Requirements are unchanged: Apple Silicon and macOS 14 or later for the app, and iOS 17 or later for ScreenClipKit. Add the Swift package `https://github.com/lludo/ScreenClip`, product **ScreenClipKit**, from version 1.1.0; the [iOS guide](https://github.com/lludo/ScreenClip/blob/main/docs/ios-sdk.md) has the details. The [privacy policy](https://screenclipai.com/privacy) now describes reports from iOS apps.

The app and disk image are signed with Developer ID, notarized by Apple, and stapled. Updates are also signed with ScreenClip's update key, and the app refuses any that are not. To verify the download, place `ScreenClip.dmg` and `SHA256SUMS` in the same folder and run:

```sh
shasum -a 256 -c SHA256SUMS
```
