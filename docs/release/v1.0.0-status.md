## Final check, November 16

Three independent reviews of the core library, the worker and app model, and the interface, documentation, and release metadata found no crash, data-loss, secret-leak, or unsafe-merge defect. These were fixed before the rebuild:

- Grok Bot evidence is staged with `--force`, so a `*.png` or `.screenclip/` ignore rule no longer drops screenshots from the hand-off or fails it.
- A validation or CI failure that repeats with the same text is sent to the agent again instead of being treated as already delivered.
- A failed `git fetch` while updating a pull request against its base no longer starts an agent repair turn; the report stays open and the next refresh retries.
- Failed checks reported for a head ScreenClip did not push no longer start a repair.
- A report that left **PR open** while another refresh was running is no longer refreshed.
- Canceling a Codex report expires its unanswered permission and input cards, so Continue and Archive stay available.
- A blocked Grok Bot pull request is marked unread once, not on every refresh.
- A pull request opened from a fork with the same branch name is not adopted as the report's own.
- A keyboard shortcut that cannot be registered is no longer saved; Settings keeps the one that works. Pressing Escape in the shortcut recorder restores the label.
- Routing reasons and the Space key name are translated.
- Privacy page: the window title of the captured app is stored with every capture and sent to the local agent, whatever the browser URL setting is; only the browser URL depends on that setting. The page said both depended on it. The Grok Bot paragraph now says the webhook and `report.json` carry ScreenClip's agent instructions and the default prompt add-on.
- The user guide's description of the Grok Bot agent link and cancel request, and of the composer's issue menu, now match the app.

## Rebuilding

Notarization credentials are in the macOS Keychain profile `ScreenClip-notary`; no credentials are stored in the repository. From a clean checkout of the tag:

```sh
export SCREENCLIP_SIGNING_IDENTITY='Developer ID Application: Ludovic Landry (D6826XDERA)'
bash scripts/build.sh release DEVELOPMENT_TEAM=D6826XDERA CODE_SIGN_STYLE=Manual CODE_SIGN_INJECT_BASE_ENTITLEMENTS=NO OTHER_CODE_SIGN_FLAGS=--timestamp
export APPLE_SIGNING_IDENTITY="$SCREENCLIP_SIGNING_IDENTITY"
export SCREENCLIP_NOTARY_PROFILE=ScreenClip-notary
bash scripts/release-dmg.sh
```

The script requires Accepted receipts, validates stapled tickets, and assesses both the app and DMG with Gatekeeper before writing `SHA256SUMS`. Attach only the verified `ScreenClip.dmg` and `SHA256SUMS` to the release. Notarization receipts stay local.

## Distribution limits

The DMG is arm64 and requires macOS 14 or later. Automatic updates are not included. Full Claude Code/Grok Bot live qualification, physical multi-monitor checks, and clean-machine installation remain tracked in the [roadmap](../roadmap.md).

The six GitHub Actions Apple secrets are not configured, so a tag push does not sign or publish anything. Local signing and notarization published this release; automated tag releases still require that setup.
