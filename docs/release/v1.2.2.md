# ScreenClip 1.2.2

Pairing an iPhone or iPad is stricter and confirmed on both screens, the queue uses far less memory, and several ways a report could get stuck are fixed.

## New

- Pairing an iOS device now has the device commit to its key before the Mac sends its own, so neither side can influence the 6-digit code you compare. **Update ScreenClip on the Mac first, then the ScreenClipKit package in your app:** ScreenClipKit 1.2.2 does not connect to ScreenClip 1.2.1 or earlier, and pairing a device with ScreenClip 1.2.2 needs ScreenClipKit 1.2.2. Devices you already paired stay paired, and an app still on ScreenClipKit 1.2.0 or 1.2.1 keeps sending reports to ScreenClip 1.2.2 until you update the package. When the two do not fit, the settings of ScreenClipKit 1.2.2 say which side to update.
- Pairing is now confirmed on both screens: tap **Codes match** on the device as well as **Confirm** on the Mac. The device keeps a new pairing only after both.

## Fixes

- ScreenClip no longer keeps full-size screenshots in memory for the queue. Thumbnails and the screenshots in a report are loaded at the size they are drawn, and the cache has a limit. A long queue could previously grow the app past 1 GB.
- A Codex request that Codex refuses no longer asks you to reconcile a chat that never started.
- The Grok Bot reminder about a missing pull request no longer undoes a cancel made at the same moment.
- An agent's request to close a report waits for GitHub when it cannot be reached, instead of being refused. A pull request GitHub does not have is still refused right away.
- Project settings left open no longer drop an app's bundle ID that ScreenClip learned meanwhile, or a Codex approval mode you changed from a report.
- The iOS server restarts by itself after a network failure, and the SDK reconnects after a busy Mac or a pairing that did not happen. The reason a pairing was refused stays on screen after the device reconnects to a Mac it was already paired with.

## Install

If you have 1.0.3 or later, ScreenClip installs this update on its own: it shows **Update to 1.2.2** in the menu bar popover once it is downloaded, or installs it the next time ScreenClip quits. **Check for Updates…** in the popover's **⋯** menu checks right away.

From 1.0.2 or earlier, download **ScreenClip.dmg** from this release, open it, and drag **ScreenClip** into **Applications**, replacing the older version. Your queue, projects and settings are kept. Requirements are unchanged: Apple Silicon and macOS 14 or later for the app, and iOS 17 or later for ScreenClipKit.

If your app uses ScreenClipKit, update the Swift package `https://github.com/lludo/ScreenClip`, product **ScreenClipKit**, to version 1.2.2 after you update the Mac. ScreenClipKit 1.2.2 needs ScreenClip 1.2.2 or later on the Mac. ScreenClip 1.2.2 still receives reports from devices paired with ScreenClipKit 1.2.0 or 1.2.1, but pairing a device needs ScreenClipKit 1.2.2. The SDK's public API is unchanged, and paired devices stay paired. The [iOS guide](https://github.com/lludo/ScreenClip/blob/main/docs/ios-sdk.md) and the [SDK documentation](https://screenclipai.com/sdk/documentation/screenclipkit) have the details.

The app and disk image are signed with Developer ID, notarized by Apple, and stapled. Updates are also signed with ScreenClip's update key, and the app refuses any that are not. To verify the download, place `ScreenClip.dmg` and `SHA256SUMS` in the same folder and run:

```sh
shasum -a 256 -c SHA256SUMS
```
