# ScreenClip 1.2.1

Reports keep going when an agent runs out of usage, long fixes get more time, and agents can close reports they fixed themselves.

## New

- When a Claude Code model reaches its usage limit, the report continues on the next lower model: Fable, then Opus, then Sonnet. The report's activity shows the switch.
- When an agent is out of usage on every model, **Hand reports to another agent when one is out of quota** moves the report to your other agent, Claude Code or Codex. The new agent picks up the same worktree with a note on what the previous one did, and carries on from there. It is on by default in **Settings → AI Agents**. With it off, or with no other agent ready, the report goes back to the queue and starts again by itself after 15 minutes. A usage limit never fails a report.
- Claude Code and Codex can close a report through ScreenClip's MCP server when they fixed it themselves, with their own pull request or commit, or found it no longer applies. The report moves to **To retest** or **Canceled**, with the agent's note in its timeline.
- The **Connections** tab in Settings is now **AI Agents**.

## Fixes

- An agent turn can run for 2 hours instead of 45 minutes. A turn that still runs out continues the same conversation once by itself, instead of failing near the end of a fix.
- Publishing no longer stops with "The following paths are ignored by one of your .gitignore files" when a project ignores `.screenclip`.
- Reports that 1.2.0 failed for a usage limit, a time limit, or that `.gitignore` error start again automatically after you update.

## Install

If you have 1.0.3 or later, ScreenClip installs this update on its own: it shows **Update to 1.2.1** in the menu bar popover once it is downloaded, or installs it the next time ScreenClip quits. **Check for Updates…** in the popover's **⋯** menu checks right away.

From 1.0.2 or earlier, download **ScreenClip.dmg** from this release, open it, and drag **ScreenClip** into **Applications**, replacing the older version. Your queue, projects and settings are kept. Requirements are unchanged: Apple Silicon and macOS 14 or later for the app, and iOS 17 or later for ScreenClipKit.

ScreenClipKit has no changes in this release. Version 1.2.1 of the Swift package `https://github.com/lludo/ScreenClip`, product **ScreenClipKit**, is the same SDK as 1.2.0 and works with ScreenClip 1.2.0 or later on the Mac. The [iOS guide](https://github.com/lludo/ScreenClip/blob/main/docs/ios-sdk.md) and the [SDK documentation](https://screenclipai.com/sdk/documentation/screenclipkit) have the details.

The app and disk image are signed with Developer ID, notarized by Apple, and stapled. Updates are also signed with ScreenClip's update key, and the app refuses any that are not. To verify the download, place `ScreenClip.dmg` and `SHA256SUMS` in the same folder and run:

```sh
shasum -a 256 -c SHA256SUMS
```
